# 武汉大学电子信息学院通知样本研究（V1）

研究日期：2026-09-22  
样本窗口：近 180 天（实际命中 2026-03-26 至 2026-09-22）  
公开来源：[武汉大学电子信息学院官网](https://eis.whu.edu.cn/)

## 1. 本轮完成了什么

本轮没有搭建完整聚合系统，只完成了第一阶段所需的三件事：

1. 确认学院网站的信息结构和历史分页方式；
2. 抓取列表、详情正文、正文链接和附件元数据，建立真实样本；
3. 逐条复核样本并设计第一版三分类规则。

采集覆盖 8 个栏目：综合通知、科研通知、学术讲座、本科生教育、学工通知、学生活动、共青团工作、留学通知。

## 2. 样本概况

共采集 109 条，详情页抓取失败 0 条，正文总计约 13.5 万字。29 条通知带有附件，共识别并按显示名称去重 76 个附件；13 条通知含正文外链，共识别 22 个链接。

| 栏目 | 样本数 | 保留 | 过滤 | 待复核 |
|---|---:|---:|---:|---:|
| 综合通知 | 8 | 1 | 6 | 1 |
| 科研通知 | 1 | 0 | 1 | 0 |
| 学术讲座 | 15 | 15 | 0 | 0 |
| 本科生教育 | 8 | 3 | 5 | 0 |
| 学工通知 | 28 | 22 | 4 | 2 |
| 学生活动 | 41 | 0 | 41 | 0 |
| 共青团工作 | 6 | 1 | 2 | 3 |
| 留学通知 | 2 | 1 | 1 | 0 |
| **合计** | **109** | **43** | **60** | **6** |

标签定义：

- `keep`：本科生可以报名、申请、参加、准备，或属于必须关注的重要事务；
- `filter`：明显是新闻回顾、宣传喜报、教师/研究生专属事项、内部任命制度，或属于 V1 明确排除的实习就业内容；
- `review`：当前没有新报名动作，但可能有异议期、名单确认或集体层面的行动价值。第一版日报中应保留，不应静默丢弃。

完整人工标签和理由位于 `data/eis/labeled_samples.csv`。原始结构化正文位于 `data/eis/notices.jsonl`。

## 3. 从真实样本观察到的规律

### 3.1 栏目是强信号，但不能单独决定

- “学生活动”在本窗口内 41 条全部是活动结束后的报道，适合作为强过滤先验。
- “学术讲座”15 条全部是未来讲座预告，具有稳定的参加价值，可以作为强保留先验。
- “学工通知”价值密度最高，28 条中 22 条直接值得保留。
- “本科生教育”混合了竞赛报名、推免通知和获奖喜报，必须看标题的行动状态。
- “科研通知”当前样本很少，且唯一一条是教师国家自然科学基金申报，不能据此永久屏蔽整个栏目。

结论：栏目可用于设定先验，但最终判断仍需结合标题和正文受众。

### 3.2 “动作尚未发生”比主题关键词更重要

同一个“竞赛”主题会出现完全相反的价值：

- “关于组织参加……竞赛的通知”是待报名机会，应保留；
- “竞赛圆满落幕”“斩获国家级奖项”“再创佳绩”是完成态新闻，应过滤。

因此不能只依赖“竞赛、科研、志愿、交流”等主题词。规则必须先识别状态：报名/申请/招募/评选，与落幕/获奖/喜报/回顾。

### 3.3 正文受众判断不可省略

标题可能误导。例如“关于选聘电子信息学院 2026 级本科新生班主任的通知”含“本科新生”和“选聘”，但正文选聘范围仅为教师，应过滤。相反，“卓越芯火计划”从标题无法确定是否适合本科生，正文明确面向即将升入大四的学生，应保留。

因此第一版至少要读取正文开头并识别：本科生、全体学生、研究生、教师、教职工、党支部等受众。

### 3.4 公示和名单不宜一刀切

拟推荐、拟聘用、推优入党等公示通常没有新的报名动作，但常带有异议期，对当事人重要。第一版将其放入 `review`，在日报的“可能需要确认”分区中保留。

已经结业、已经获奖、已经公布且没有后续动作的名单则可以过滤。

### 3.5 附件与外链是正文的一部分

推免、综测、国际交流资助、学生岗位招聘等高价值通知往往把申请表、评分细则和操作手册放在附件中。仅保存详情页文本会丢失关键材料。本轮已做到：

- 解析学校统一下载接口；
- 兼容新版和旧版两个附件入口；
- 按附件显示名称去重；
- 保留正文中的校内、校外链接。

本阶段尚未下载和解析 PDF、DOCX、XLSX 的文件内容。

## 4. 第一版筛选顺序

规则顺序很重要，建议按以下流程执行：

1. **范围过滤**：过滤教师/教职工专属、研究生专属、实习招聘会、内部任命与制度；推免通知不能因标题出现“研究生”而误删。
2. **完成态过滤**：过滤学生活动新闻、喜报、落幕、获奖、斩获、再创佳绩等。
3. **结果态分流**：拟推荐名单、拟聘用名单、推优入党公示进入 `review`；纯结业或已完成名单可过滤。
4. **行动词保留**：报名、申请、申报、招募、招聘、征集、选拔、选聘、评选、推荐、参加、资助、奖学金。
5. **重要事务保留**：综测、推免、转专业、选课、考试、报到注册、导师双选、假期安排、发展团员。
6. **栏目先验**：学术讲座默认保留；留学通知加分；学生活动完成态报道默认过滤。
7. **其余进入 `review`**：第一版宁可多保留，不做无依据的静默过滤。

规则实现在 `src/whu_notice_research/rules.py`。其在本轮用于制定规则的 109 条样本上与人工标签一致 109/109。这个数字只表示规则完整编码了本批观察结论，**不是独立测试准确率**，不能用于证明后续泛化效果。

## 5. 采集结构与可扩展性

每条记录保存以下字段：

| 字段 | 含义 |
|---|---|
| `source_id`, `source_name` | 来源标识与栏目名 |
| `published_at` | 发布日期 |
| `title`, `summary` | 列表标题与摘要 |
| `url` | 详情页规范化 URL |
| `detail_title`, `detail_column` | 详情页标题与栏目 |
| `body_text` | 清洗后的正文 |
| `attachments` | 附件名称与下载 URL |
| `links` | 正文普通链接 |
| `fetched_at`, `fetch_error` | 抓取时间与错误信息 |

学院栏目配置独立保存在 `config/eis_sources.json`。后续添加武汉大学其他官网时，可以复用 `Notice` 数据结构、规则接口和导出格式，只新增站点适配器，避免把每个网站写成一套互不兼容的脚本。

## 6. 已知局限与验证计划

1. 样本只有一个学院和一个 180 天窗口，季节性明显；开学、评奖和推免季的通知比例偏高。
2. 规则是基于同一批样本制定的，尚无时间外验证集。
3. 学生活动栏目本期全部可过滤，但未来也可能发布活动报名，不能永远只按栏目名丢弃；生产版本应保留行动词兜底，并监测被过滤标题。
4. 附件只保存元数据，尚未解析文件中的截止日期、资格条件和表格。
5. 本轮没有提取统一的报名截止日期、对象、地点和联系方式。

下一步不应马上扩展所有站点，而应把这套单站采集连续跑 2 至 4 周：

- 所有 `keep` 和 `review` 都进入测试日报；
- 每日附上一小段被过滤标题，便于发现漏报；
- 每周抽查至少 10% 的过滤项；
- 新数据单独作为时间外验证集，不回写旧标签后再宣称准确率；
- 根据误报和漏报再决定是否进入“单网站稳定运行”阶段。
