# 武汉大学公众号自动采集

## 工作方式

公众号与官网共用 `Notice`、SQLite、规则筛选、DeepSeek、附件解析、跨来源事件去重和飞书日报。公众号文章优先由微信读书会话发现，同时运行公开合集页和低频搜狗索引；任一通道失败不会终止其他公众号或官网。

系统不绕过验证码、微信风控或访问控制。微信读书会话过期时只自动续期一次；失败后切换公开备用来源。某个“公众号 / 采集器”连续三次失败才触发健康告警，“没有新文章”不视为故障。

## 一次性初始化

安装依赖后执行：

```powershell
python scripts/init_wechat.py --state-bucket project-871ad35a-5a6f-40a4-8f0-whu-state
```

程序会打开微信读书二维码。扫码确认后，凭证写入 `data/private/wechat_credentials.json`，该目录已被 Git 忽略；随后程序低频查询第一批账号，只把公开认证信息能确认属于武汉大学的账号设为 `verified=true` 和 `enabled=true`。未核验账号保持关闭，不会按名称猜测。优先级前 3 个账号立即开始 7 天影子采集（入库和评估但不推送），其余已核验账号在第 8 天自动启用，不需要再次操作。

凭证上传到私有 Cloud Storage 对象 `private/wechat_credentials.json`，不会进入公开仓库、日志或飞书。Cloud Run 每次启动下载凭证；自动续期后使用对象 generation 前置条件写回，避免并发覆盖。

注册表在 `config/wechat_accounts.json`。支持的标识包括 `biz`、`book_id`、种子文章和合集页；日常运行不需要转发文章或补链接。

## 解析与成本保护

- 公众号正文提取标题、发布日期、正文、图片、附件和外链。
- PDF、DOCX、XLSX 及报名页进入现有附件增强流程。
- 正文不足 500 字且包含图片时，最多 OCR 5 张图。
- Google Vision 每月硬限制 900 张；超过后自动使用容器内的中文 Tesseract。
- 首次启用只建立最近 30 天基线，历史文章不补发；后续只处理游标之后的新文章。

## 云端阶段

`scripts/configure_google_schedules.ps1` 配置北京时间任务：

| 时间 | 阶段 |
| --- | --- |
| 21:30 | 公众号主同步 |
| 21:42 | 只重试失败账号与备用来源 |
| 21:45 | 全站采集、附件/OCR/AI 预处理 |
| 21:55 | 冻结当日日报集合 |
| 22:00 | 只读取冻结集合并发送 |
| 22:11 / 22:41 / 23:11 | 幂等补偿发送 |

22:00 若冻结阶段因排队未完成，会使用数据库中已经持久化的当日结果建立无网络回退快照再发送。当天成功后其余发送任务自动跳过；23:30 后停止。

## 安全边界

- 仅保存筛选所需文字、元数据和原文链接，不长期镜像公众号全文或图片。
- 公开 GitHub 只能保存注册表，不能保存 Cookie、Token、二维码或设备标识。
- Cloud Run Job 并发固定为 1；SQLite、游标和凭证写回均使用代际条件。
- 公众号页面要求人工验证时记录 `auth_expired` 或 `rate_limited`，绝不自动识别验证码或使用代理池。
